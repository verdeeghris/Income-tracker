Реализацию исправлений нужно делать в **Act Mode** — переключитесь селектором режима внизу чата, все находки ниже перейдут туда как контекст.

## Summary
Одностраничное React-приложение для учёта доходов по договорам ГПХ: пользователь отмечает на календаре проекты/деятельности с суммой, видит что выплачено, а что нет. Вся логика — в одном файле `src/App.jsx`; состояние хранится в `localStorage`, бэкенда нет. Стек: **Vite + React 19 + Tailwind CSS 3.4 + lucide-react**. Важное открытие: модули `src/WorkCalendar.jsx`, `src/constants.js`, `src/dateUtils.js`, `src/finance.js` — **мёртвый код** прошлой версии приложения (никто их не импортирует), но в них есть готовые решения для ваших багов (формат даты «22 августа 2026», налоговая математика).

## Architecture
- Однофайловый SPA без роутера и бэкенда: `App` владеет всем состоянием, `WorkCalendar` объявлен внутри `App.jsx`.
- Три ключа `localStorage`: `gph_theme_v2` ('light'|'dark'), `gph_projects_v2` (массив проектов `{id, date:'YYYY-MM-DD', title, amount, color, repeat}`), `gph_paid_instances_v2` (карта оплат по ключу `${projectId}_${dateKey}` — статус оплаты конкретного экземпляра повторяющегося проекта).
- Повторяющиеся проекты **не персистятся поэкземплярно** — каждый рендер разворачиваются функцией `expandRecurringProjects` в пределах выбранного года.

## Разбор ваших багов (причина → решение)

1. **Годы только 2025–2027** — захардкоженный массив `[2025, 2026, 2027]` в `<select>` года в шапке. Решение: динамическая генерация диапазона; по вашим требованиям выбор даты вообще должен переехать в панель НАД календарём (клик по дате → изменение года/месяца/дня), а селекты — убраться.
2. **Скачок страницы при режиме «Месяц»** — месячная сетка выше вьюпорта → появляется скроллбар → ширина страницы сужается → контент сдвигается (на Windows скроллбар занимает ~17px). Решение одной строкой в `index.css`: `html { scrollbar-gutter: stable; }`.
3. **Тема не переключается** — в коде две конфликтующие системы тем. Обработчик кнопки формально корректен (поэтому иконка меняется), НО: `index.css` красит фон `body` и плейсхолдеры через CSS-переменные, которые живут в скоупе класса `.dark` — а этот класс **нигде не ставится на DOM**. `darkMode: 'class'` в tailwind.config тоже мёртв — в коде нет ни одного `dark:` варианта. Решение: единый источник правды — `useEffect` с `document.documentElement.classList.toggle('dark', isDark)` и перевод стилей на одну систему.
4. **Шрифт** — веб-шрифт не подключён вообще (в `index.html` нет ссылок на шрифты): системный стек + `font-mono` для цифр. Решение: подключить строгий гротеск с кириллицей (Inter / Manrope / Golos Text / Onest — «как Montserrat, но не он») + табличные цифры `'tnum'` для денег вместо моно.
5. **Дата ГГГГ-ММ-ДД** — модалка выводит сырой ключ `modalDate`. Готовое решение лежит в мёртвом `dateUtils.js`: `MONTHS_GEN` + `formatLongDate()` дают ровно «22 августа 2026» — нужно перенести в активный код.
6. **Плейсхолдеры дублируют лейблы** — «Название» под «Название проекта», «0» под «Оплата в рублях». Заменить примерами или убрать.
7. **Непонятные 13% в трёх блоках** — блоки считают в разных базах: «Ожидает выплаты» — нетто (`amount * 0.87`, процент захардкожен), «Выплачено» — **гросс**, «Всего» — гросс за весь год (хотя подписано «За выбранный период»). Отсюда и путаница. Решение: разделить явно — «Начислено по договорам», «Получено на руки (за минусом налога)», «Ожидается к получению», процент налога сделать явным.
8. **Скачок при открытии модалки** — эффект модалки ставит `body.overflow='hidden'`, скроллбар исчезает, контент сдвигается. Лечится тем же `scrollbar-gutter: stable` из п.2.

## Дополнительные баги, найденные при чтении (не из вашего списка)
- **Смена года не сбрасывает день**: при выбранном 31-м числе переход на февраль даёт ролловер JS-Date → ячейка «31» молча показывает 3 марта.
- **Проекты вне выбранного года исчезают** из вида (окно развёртки = выбранный год) — в связке с урезанным списком лет данные «пропадают».
- **Ежедневный повтор обрезается лимитом 366 итераций** от даты начала серии.
- **Редактирование любого экземпляра меняет всю серию** (кроме галочки «Выплачено»); перенести проект на другую дату невозможно — поля даты в форме нет.
- Чекбокс «Выплачено»: клик по тексту не переключает (обработчик на внутреннем `div`), клавиатурой недоступен.
- Классы `scrollbar-none` и `backdrop-blur-xs` не существуют в Tailwind 3.4 — не работают.
- Клик по дню всегда открывает модалку создания, даже если в дне есть проекты; редактирование — только по мелким чипам.
- Нет закрытия модалки кликом по оверлею; нет анимаций появления.
- `lang="en"` и title «income-tracker» в `index.html` при русскоязычном приложении.

## Ключевые абстракции и поток данных
- **Состояние `App`**: ~15 `useState` (тема, год/месяц/день, режим, проекты, оплаты, модалка+форма), синхронизация с localStorage через три `useEffect`.
- **`expandRecurringProjects`**: базовые проекты → виртуальные экземпляры с `instanceKey = id_дата`; оплата каждого экземпляра — из `paidInstances`.
- **Поток**: клик по дню → модалка → сабмит → запись в `projects` + `paidInstances` → localStorage → разворот повторов → `analytics` → рендер календаря/дашборда.
- **Инвариант**: удаление проекта обязано чистить его записи в `paidInstances` (сейчас — по ненадёжному `startsWith(id)`).
