# Income Tracker («Трекер ГПХ») — Обзор кодовой базы

## Summary
Одностраничное React-приложение для учёта доходов по договорам ГПХ: пользователь отмечает на календаре проекты/деятельности с суммой, видит что выплачено, а что нет. Вся логика — в одном файле `src/App.jsx`; состояние хранится в `localStorage`, бэкенда нет. Стек: **Vite + React 19 + Tailwind CSS 3.4 + lucide-react**. В репозитории также лежат 4 модуля-«призрака» от предыдущей версии приложения (`WorkCalendar.jsx`, `constants.js`, `dateUtils.js`, `finance.js`) — они **никем не импортируются** и являются мёртвым кодом, но содержат полезные утилиты (форматирование дат в родительном падеже, налоговая математика), которые стоит реюзать при доработке.

## Architecture
- **Паттерн**: однофайловый SPA без роутера и бэкенда. Компонент `App` владеет всем состоянием; `WorkCalendar` (объявлен внутри `App.jsx`) — презентационный дочерний компонент.
- **Персистентность**: три ключа `localStorage`:
  - `gph_theme_v2` → `'light' | 'dark'`
  - `gph_projects_v2` → JSON-массив проектов `{ id, date: 'YYYY-MM-DD', title, amount: number, color, repeat }`
  - `gph_paid_instances_v2` → JSON-объект вида `{ "${projectId}_${dateKey}": boolean }` — статус оплаты **конкретного экземпляра** (нужно для повторяющихся проектов)
- **Точка входа**: `index.html` → `src/main.jsx` (StrictMode) → `src/App.jsx`.
- **Стилизация**: Tailwind JIT со «ручным» переключением тем через тернарники `isDark ? ... : ...`. Параллельно в `index.css` существует вторая, неиспользуемая система тем на CSS-переменных с классом `.dark`, а в `tailwind.config.js` задан `darkMode: 'class'` — но класс `.dark` **нигде не вешается на DOM**. Это источник бага с темой (см. ниже).

## Key Abstractions (все — внутри `src/App.jsx`)

### Состояние `App`
- **Ответственность**: единственный источник правды. ~15 `useState`: тема, выбранные год/месяц/день, режим календаря (`day|week|month`), массив `projects`, карта `paidInstances`, флаги модалки и её формы (title/amount/color/isPaid/repeat).
- **Жизненный цикл**: инициализация из `localStorage` через ленивые `useState(() => ...)`, запись обратно тремя `useEffect`.
- **Кто использует**: рендер шапки, дашборда, блока «Ожидают оплаты», календаря, модалки.

### `expandRecurringProjects(projects, startDateStr, endDateStr, paidInstances)`
- **Файл**: `src/App.jsx`
- **Ответственность**: превращает базовый список проектов в «развёрнутый» список экземпляров. Неповторяющийся проект → один экземпляр с `instanceKey = id_date`. Повторяющийся (`daily/weekly/monthly/yearly`) → виртуальные экземпляры на каждую дату повтора внутри окна `[startDate, endDate]`, каждый со своим `instanceKey = id_дата` и собственным статусом `isPaid` из `paidInstances`.
- **Ключевой инвариант**: экземпляры НЕ персистятся — они каждый раз вычисляются. Персистится только базовый проект + карта оплат по экземплярам.
- **Подводный камень**: окно развёртки = выбранный год (`${selectedYear}-01-01 … ${selectedYear}-12-31`), а лимит итераций `index < 366` считается ОТ ДАТЫ НАЧАЛА проекта → ежедневный повтор старше года «не дотягивается» до далёких лет; проекты с датой вне выбранного года вообще исчезают из вида.

### `WorkCalendar` (внутренний компонент в `App.jsx`)
- **Ответственность**: сетка календаря в трёх режимах. `getMonthMatrix()` строит 6×7 матрицу месяца с понедельника; `visibleWeeks` срезает её до дня/недели в соответствующих режимах.
- **Пропсы**: `year, month, selectedDayNumber, mode, projects, onSelectDay, onProjectClick, isDark`.
- **Особенности**: клик по ячейке дня → `onSelectDay` → сразу открывается модалка СОЗДАНИЯ проекта; клик по чипу проекта внутри ячейки (со `stopPropagation`) → модалка редактирования. Переполнение чипов дня скрыто внутренним скроллом `max-h-[100px]` (класс `scrollbar-none` — не существует в TW 3.4, не работает).

### `analytics` (useMemo)
- **Ответственность**: три суммы + список неоплаченных. **Несогласованная база**: «Ожидает выплаты» показывает НЕТТО (`amount * 0.87`, НДФЛ захардкожен), «Уже выплачено» — **ГРОСС** оплаченных, «Всего по ГПХ» — гросс всего за **год** (подпись «За выбранный период» лжёт). Именно это вызывает путаницу пользователя («непонятное вычитание 13%»).

### `MINIMAL_PALETTE` / `REPEAT_OPTIONS`
- Константы палитры (6 пастельных цветов с парами light/dark) и вариантов повторения. Локальные дубликаты мёртвых `JOB_COLORS`/налоговых режимов из `constants.js`.

### Модальное окно проекта
- Одна форма на создание и редактирование (флаг `activeProject`). Поля: название, сумма (number), повторение (select), цвет (свотчи), кастомный чекбокс «Выплачено». Кнопки: удалить (только в режиме редактирования) и «Сохранить». Закрытие: крестик или ESC (**клик по оверлею не закрывает**). Дата в форме НЕ редактируется — перенести проект на другой день невозможно.

## Data Flow
1. Клик по ячейке дня → `handleSelectDay(dateKey, dayNum)` → сброс формы → `setIsModalOpen(true)`.
2. Сабмит формы → `handleSaveProject`:
   - создание: новый объект `{id: Date.now(), date, title, amount, color, repeat}` в `projects` + запись `paidInstances[id_date] = formIsPaid`;
   - редактирование: `projects.map` обновляет **базовый проект целиком** (название/сумма/цвет/повторение — для ВСЕХ экземпляров серии), а `paidInstances[instanceKey]` фиксирует оплату только конкретного экземпляра.
3. `useEffect` пишет `projects` и `paidInstances` в `localStorage`.
4. `expandedProjects` (useMemo) разворачивает повторы в пределах выбранного года.
5. `analytics` считает суммы по `expandedProjects`; блок «Ожидают оплаты» строит чипы из `unpaidList`.
6. `WorkCalendar` фильтрует `expandedProjects` по `p.date === dateKey` и рисует чипы.

## Неочевидные поведения, инварианты и разбор заявленных багов

### Разбор ошибок из запроса (причина → где лечить)
1. **Годы ограничены (2025–2027)** — в шапке захардкожен массив `[2025, 2026, 2027]` в `<select>`. Лечится генерацией диапазона динамически; по требованиям нужен бесконечный календарь с навигацией над ним, т.е. селекты вообще стоит заменить.
2. **Скачок страницы при включении режима «Месяц»** — месячная сетка (~6 строк × min-height 100–120px + шапка + дашборд) выше вьюпорта → появляется вертикальный скроллбар → ширина вьюпорта сужается → центрированный контент сдвигается. На Windows 10 скроллбар занимает реальную ширину (~17px). Лечение: `html { scrollbar-gutter: stable; }` (или постоянный `overflow-y: scroll`) — одним свойством чинит и пункт 8.
3. **Тема не переключается (иконка меняется)** — расщепление на две системы тем. Обработчик `setTheme(isDark ? 'light' : 'dark')` формально корректен и классы `App`-дивов реально меняются, НО: (а) `index.css` красит `body` через `var(--app-bg)` и плейсхолдеры через `var(--muted)` — эти поверхности живут в скоупе `.dark`, который **никогда не добавляется на `<html>`/`<body>`**, поэтому фон страницы и плейсхолдеры вечно светлые; (б) `darkMode: 'class'` в конфиге Tailwind мёртв — ни одного `dark:` варианта в коде нет. Надёжное решение: один источник правды — `useEffect`, который делает `document.documentElement.classList.toggle('dark', isDark)`, перевод стилей на `dark:` варианты / CSS-переменные и удаление ручных тернарников. Также стоит сбросить старое значение `gph_theme_v2` при миграции.
4. **Шрифт** — веб-шрифт не подключён вовсе (в `index.html` нет ни одной ссылки на шрифты): работает системный стек Tailwind + `font-mono` (системный моно) для цифр и дат. Нужно подключить строгий геометрический гротеск с кириллицей (Inter / Manrope / Golos Text / Onest — «как Montserrat, но не Montserrat») через `<link>` в `index.html` + `theme.fontFamily.sans` в tailwind.config; для цифр использовать табличные цифры (`font-feature-settings: 'tnum'`) вместо моно.
5. **Дата в формате ГГГГ-ММ-ДД** — модалка рендерит сырой ключ: `` `Новый проект • ${modalDate}` ``, то же самое в чипах неоплаченных (`{p.date}`). Готовое решение уже лежит в мёртвом `dateUtils.js`: `MONTHS_GEN` + `formatLongDate()` дают ровно «22 августа 2026».
6. **Плейсхолдеры дублируют лейблы** — «Название проекта»/placeholder «Название», «Оплата в рублях»/placeholder «0». Заменить на осмысленные примеры или убрать.
7. **Непонятные блоки с 13%** — см. `analytics`: смешаны нетто и гросс, 13% захардкожено (`amt * 0.87`), подпись «За выбранный период» фактически суммирует весь год. Предлагаемая модель: «Начислено по договорам (гросс)» / «Получено на руки (нетто выплаченных)» / «Ожидается к получению (нетто + гросс подписью)», процент налога — явной константой/настройкой, а не магическим 0.87.
8. **Скачок при открытии модалки в режиме «Месяц»** — эффект модалки ставит `document.body.style.overflow = 'hidden'`, скроллбар страницы исчезает → контент сдвигается вправо. То же лечение, что в п.2: `scrollbar-gutter: stable` на `html` — тогда блокировка скролла не даёт скачка.
9. **Бесконечный календарь / выбор даты над календарём** — сейчас выбор даты — это два `<select>` в шапке (год урезан, месяц), отдельного контрола даты над календарём нет; в режимах день/неделя нет кнопок «назад/вперёд» (они были только в мёртвом `WorkCalendar.jsx`).

### Дополнительные баги и ловушки, найденные при чтении (не из списка пользователя)
- **Ролловер даты при смене года**: `onChange` года НЕ сбрасывает `selectedDayNumber` (месяц — сбрасывает на 1). При выбранном 31-м числе переход на февраль даёт `new Date(year, 1, 31)` → 3 марта: ячейка «31» молча показывает чужой `dateKey`.
- **Данные вне выбранного года недостижимы**: окно развёртки = выбранный год; проект с датой 2024 года не виден вообще (в связке с урезанным списком лет — данные «пропадают»).
- **Ежедневный повтор обрезается лимитом `index < 366`** от даты начала серии — длинные ежедневные серии перестают попадать в далёкие годы.
- **Редактирование экземпляра меняет всю серию** (кроме `isPaid`): title/amount/color/repeat пишутся в базовый проект. Пользователь может ожидать правку только одного экземпляра. Перенос проекта на другую дату невозможен в принципе (поля даты в форме нет).
- **Кастомный чекбокс «Выплачено»**: `onClick` висит на внутреннем `div`; клик по тексту «Выплачено» не переключает, клавиатурой недоступен (нет `input`/`role`).
- **`scrollbar-none` и `backdrop-blur-xs`** — несуществующие классы Tailwind 3.4 (второй появился лишь в TW 4.x): внутренний скролл чипов показывает нативный скроллбар, блюр оверлея не применяется.
- **Клик по дню всегда открывает модалку создания**, даже если в дне есть проекты — редактирование доступно только по маленьким чипам.
- **Очистка `paidInstances` при удалении** идёт по `k.startsWith(project.id)` — префиксное сравнение ID на основе `Date.now()` теоретически коллидирует; надёжнее точное сравнение префикса `${id}_`.
- **Нет закрытия модалки кликом по оверлею**; нет анимаций появления (только `transition-colors`).
- **`lang="en"` и title «income-tracker»** в `index.html` — приложение русскоязычное, называется «Трекер ГПХ».
- **Мусор шаблона**: `public/icons.svg`, `src/assets/*`, палитра `pastel` в tailwind.config, CSS-переменные в index.css (частично), локальная функция `getDaysInMonth` в App.jsx — не используются.

### Инварианты системы
- Экземпляры повторяющихся проектов всегда вычисляемые; их оплата живёт ТОЛЬКО в `paidInstances` по ключу `id_date`.
- `dateKey` везде в формате `YYYY-MM-DD` (локальная `formatDateKey`) — на нём держатся и хранение, и фильтрация, и ключи оплат. Любая новая дата должна проходить через этот форматтер.
- Удаление проекта обязано чистить и его записи в `paidInstances`, иначе появятся «висячие» оплаты.

## Suggested Reading Order
1. `src/App.jsx` — здесь вся логика; читать сверху вниз: палитра → утилиты дат → `expandRecurringProjects` → `WorkCalendar` → `App`.
2. `src/index.css` + `tailwind.config.js` — понять расщепление системы тем (корень бага №3).
3. `index.html` + `src/main.jsx` — точка входа, отсутствие шрифтов (баг №4).
4. `src/dateUtils.js` — готовые форматтеры дат для бага №5 (сейчас мёртвые).
5. `src/finance.js` — образец аккуратной налоговой математики для переделки финблоков (баг №7).
6. `src/WorkCalendar.jsx` + `src/constants.js` — референс прошлой версии: навигация ←/→, палитры, режимы (понять, что можно забрать, а что удалить).
